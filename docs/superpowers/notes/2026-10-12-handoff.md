## Key results to remember

- Decision 0003: E4B on CPU reads a prompt at 43 to 59 tokens/s and writes at
  6 to 7 tokens/s. A 30-minute transcript is 9,984 tokens. The prefix reuse
  works (the second task starts in under 1 s). Without live reading, the
  notes job takes 6 to 7 minutes.
- Decision 0002: Whisper `base.en` costs 0.13 to 0.19 s of compute per second
  of speech.

## How the work runs

- The plans use subagent-driven development: one implementer agent for each
  task, a code review after each task or group, and fix rounds.
- Worktrees go in `.worktrees/` inside the repository (ignored by git).
- Write all documents, comments, and commit messages in Simplified Technical
  English (ASD-STE100). The owner's global instructions require it.
- Commit messages end with a `Co-Authored-By` line and a `Claude-Session`
  line.
- Never use a bare `git stash`. The stash is shared between worktrees.
- Logs never contain user content: transcript text, notes, prompts, outputs,
  or file content.
- Commit, push, and pull requests only when the owner asks.

## Machine setup

- Linux x86_64 with AVX2, Python 3.11 or later, `uv`, CMake, and a C++
  compiler (`sudo apt install cmake g++`). `uv sync` builds llama-cpp-python
  from source (about 1 minute).
- Models go to `~/.local/share/forenote/models`. Copy that directory from the
  old machine, or download again: `uv run forenote-cli models download` for
  the tier of the machine. The spike and the model tests also need
  `gemma-4-e2b-q4_0` (3.35 GB). The download checks the SHA-256.
- Run `uv run pytest -q` (no models), `-m models` (needs the models), and
  `-m audio` (needs PipeWire or PulseAudio).
